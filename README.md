# Cashback Campaign Analytics

> **Учебный проект на синтетических данных.** Все клиенты, операции и начисления сгенерированы скриптом `scripts/01_generate_data.py` с фиксированным seed. Эффект кампании заложен в генерацию. Результаты демонстрируют методику анализа и **не являются результатами реального банка**.

**Статус:** в работе. Разделы с результатами заполняются только после выполнения анализа.

## 1. Бизнес-задача

Банк провёл кампанию с повышенным кешбэком для части клиентов. Нужно решить: **масштабировать кампанию, изменить её условия или отказаться от неё.**

**Главный бизнес-вопрос:** принесла ли кампания дополнительную прибыль банку с учётом затрат на кешбэк, и для каких сегментов клиентов её стоит масштабировать, изменить или отключить?

Вопросы анализа:
1. Увеличила ли кампания активность клиентов и расходы по картам?
2. Статистически значим ли эффект?
3. Какие сегменты клиентов реагируют лучше?
4. Какова дополнительная прибыль или убыток банка с учётом стоимости кампании?
5. Что рекомендовать: масштабировать, изменить условия или отказаться?

## 2. Условия кампании

| Параметр                        | Значение                                                            |
|---------------------------------|---------------------------------------------------------------------|
| Период до кампании (pre)        | 01.03.2026 – 30.04.2026                                             |
| Период кампании                 | 01.05.2026 – 30.06.2026                                             |
| Базовый кешбэк (все клиенты)    | 1% на все покупки                                                   |
| Предложение для тестовой группы | 5% (то есть +4%) в категориях «Кафе и рестораны» и «Онлайн-покупки» |
| Лимит дополнительного кешбэка   | 5 000 ₸ в месяц на клиента                                          |
| Контрольная группа              | обычные условия (1%)                                                |

## 3. Дизайн эксперимента и метрики

- **Единица рандомизации и анализа:** клиент. Назначение в группы случайное, примерно 50/50.
- **Принцип анализа:** intention-to-treat — в расчёт входят все назначенные клиенты, включая тех, у кого не было покупок (их расходы = 0).
- **Основная метрика (primary):** средние расходы по карте на клиента за период кампании, за вычетом возвратов.
- **Дополнительные метрики:** доля активных клиентов (≥ 1 покупка за период), число покупок на клиента, расходы в акционных категориях.
- **Защитные метрики (guardrail):** расходы в неакционных категориях (не перераспределились ли траты), стоимость дополнительного кешбэка на клиента.
- **Гипотезы для основной метрики:** H0 — средние расходы в тестовой и контрольной группах равны; H1 — различаются (двусторонний тест). Уровень значимости α = 0,05, целевая мощность 80%.
- **Сегменты** строятся только по поведению **до** кампании, чтобы сама кампания не влияла на состав сегментов.
- **Финансовый результат** считается отдельно: рост оборота ≠ доход банка. Доход оценивается через сценарные допущения (ставка interchange и др.), которые явно отделены от фактических данных.

## 4. Данные

| Таблица                   | Гранулярность (1 строка =)   | Ключ             | Описание                                                           |
|---------------------------|------------------------------|------------------|--------------------------------------------------------------------|
| `clients.csv`             | клиент                       | `client_id`      | дата открытия карты, возраст, тип города, уровень карты            |
| `campaign_assignment.csv` | клиент                       | `client_id`      | группа `test` / `control`, дата назначения                         |
| `transactions.csv`        | операция                     | `transaction_id` | дата, сумма (₸; возвраты — отрицательные), категория, тип операции |
| `cashback_accruals.csv`   | клиент × месяц × тип кешбэка | `accrual_id`     | начисления `base` и `campaign_extra`, ₸                            |

Связи: все таблицы соединяются по `client_id`. Суммы в тенге (₸). В выгрузке намеренно оставлены типичные проблемы качества — они разбираются в `sql/01_data_quality.sql`.

## 5. Структура проекта

```
Cashback-Campaign-Analytics/
├── README.md            — описание проекта, методология, выводы
├── requirements.txt     — Python-библиотеки
├── scripts/             — Python: генерация данных, запуск SQL, A/B-тест
├── sql/                 — SQL-запросы (DuckDB): качество данных, метрики, сегменты
├── data/raw/            — исходные синтетические CSV
├── data/processed/      — подготовленные таблицы для Power BI и Excel
├── powerbi/             — дашборд .pbix
├── excel/               — финансовая модель .xlsx
├── reports/             — таблицы результатов
└── images/              — графики и скриншоты дашборда
```

## 6. Как воспроизвести

```bash
python3 -m venv .venv
source .venv/bin/activate                              # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python scripts/01_generate_data.py                     # синтетические данные → data/raw/
python scripts/run_sql.py sql/01_data_quality.sql      # загрузка CSV и проверка качества
python scripts/run_sql.py sql/02_client_mart.sql       # очистка, витрина клиентов, сегменты
python scripts/run_sql.py sql/03_group_comparison.sql  # описательное сравнение групп
python scripts/04_ab_test.py                           # A/B-тест, выгрузка для Power BI и Excel
```
